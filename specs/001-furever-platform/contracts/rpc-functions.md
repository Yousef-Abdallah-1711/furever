# Contract: Database RPC functions (Phase 1)

All RPC functions are Postgres functions called via `POST /rest/v1/rpc/<function>`, validated against the
same Zod schemas the clients use (constitution IV, V). Errors use the codes in
[error-codes.md](./error-codes.md). **Security mode is stated explicitly per function below — there is no
default.** `security definer` functions additionally set `set search_path = ''` and perform their own
explicit `auth.uid()` / caller-role checks inside the function body before touching any row, precisely
because `security definer` bypasses the calling role's RLS and the function itself becomes the only gate.

## Privilege locks (apply before any function below is trusted)

- `INSERT`/`UPDATE`/`DELETE` on `appointments` and `queue_tickets` are **revoked from `authenticated`**.
  The only way to write either table is through one of the `security definer` RPCs below — never a direct
  PostgREST table write, from any role including `clinic_staff` and `admin`.
- `get_available_slots` and `get_queue_status` return **only aggregates or slot times** — a list of open
  start times, or `{ my_number, now_serving, people_ahead, estimated_wait_minutes_low/high }` for the
  calling owner's own appointment. Neither function ever returns another owner's identity, pet, or ticket
  row; `get_queue_status` takes the caller's own `p_appointment_id` and the function body itself re-checks
  `owner_id = auth.uid()` before computing anything, independent of whatever RLS would have allowed on a
  direct read.

| `cancel_appointment(p_appointment_id, p_reason)` | `security definer`; checks caller is either the appointment's `owner_id` or `clinic_staff` of its `clinic_id` before any write | `owner` or `clinic_staff` | appointment id, reason (required for staff, optional for owner inside the free window) | **Owner caller**: if `now() < starts_at - interval '2 hours'`, cancels, frees the slot, sets `cancelled_by_role = 'owner'`; otherwise raises `CANCEL_WINDOW_PASSED` and performs no write. **`clinic_staff` caller**: always allowed, `p_reason` is required (raises `VALIDATION_FAILED` if blank), sets `cancelled_by_role = 'clinic_staff'`. | `reschedule_appointment(p_appointment_id, p_new_starts_at)` | `security definer`; same caller check as `cancel_appointment` | `owner` or `clinic_staff` | appointment id, new time | Cancel + rebook in one transaction; the exclusion constraint still applies to the new slot; nothing changes if either half would fail. **Assumption, not yet confirmed in `spec.md`** (see `plan.md` → Open Questions): an **owner** reschedule follows the **same 2-hour rule as cancellation** by default (reject with `CANCEL_WINDOW_PASSED` inside the window); **`clinic_staff`** may reschedule at any time, same as cancel | BKG-05 |
| `check_in_appointment(p_appointment_id_or_code, p_via)` | `security definer`; checks caller is either the appointment's `owner_id` (QR path) or `clinic_staff` of its `clinic_id` (code-typed path) | `owner` (via QR) or `clinic_staff` (via typed code) | either the appointment id (from a scanned QR) or the typed `booking_code`; `p_via` is `'qr'` or `'code'` | **QR payload**: a signed token containing `{ appointment_id, booking_code }` (HMAC-signed with a server-side secret so a photographed QR can't be forged into checking in a different appointment); the function verifies the signature, then that the decoded `booking_code` matches the stored one. **Typed-code path**: the function looks up the appointment by `booking_code` directly (constant-time compare). **Check-in rules** (apply to both paths): the appointment's `status` must be `confirmed` (not already `checked_in`/`completed`/`cancelled` — a second check-in attempt is rejected, one ticket per appointment is also enforced by the unique constraint on `queue_tickets.appointment_id`); `queue_date` must be the appointment's own date in `Africa/Cairo`; the clinic path additionally requires the caller to be staff of that appointment's `clinic_id`. On success, creates the queue ticket: `ticket_number` is `max(ticket_number) + 1` for `(doctor_id, queue_date)`, starting at 1 each day; the app composes the display string from `doctors.queue_prefix` + `ticket_number` (e.g. `A-14`) — the RPC never returns a formatted string, only the integer and the prefix | QUE-01 (PRD amendment 1) |
| `call_next_ticket(p_doctor_id)` | `security definer`; checks caller is `clinic_staff` of that doctor's clinic | `clinic_staff` | doctor id | Moves the oldest `waiting` ticket for that doctor/today to `called`; queues a `queue_next` push to that ticket's owner, and a second `queue_next` to the owner two places behind (per QUE-03's "two places away" rule) | QUE-03, CS-07 |
| `complete_appointment(p_appointment_id)` | `security definer`; same staff check as `call_next_ticket` | `clinic_staff` | appointment id | Sets `queue_tickets.status = 'done'`, `appointments.status = 'completed'`, queues the `review_prompt` notification | CS-07, REV-01 |
| `get_queue_status(p_appointment_id)` | `security definer`; checks `auth.uid()` = the appointment's `owner_id` before computing anything (see Privilege locks above) | `owner` | appointment id | Returns `{ my_number, now_serving, people_ahead, estimated_wait_minutes_low, estimated_wait_minutes_high, estimated_wait_unavailable }`. `people_ahead` = count of `waiting`/`called`/`in_progress` tickets for the same doctor/day with a smaller `ticket_number`. The estimate = `people_ahead * avg(services.duration_min)` over those ahead's booked services, rounded to a 5-minute-bucketed range; if `people_ahead = 0` the client shows "You are next" and this RPC still returns the raw count for that check; if the average cannot be computed (no service duration data), the two `estimated_wait_minutes_*` fields are null and the client falls back to showing only `people_ahead`. **Never** returns a single exact-minute value — only a low/high pair or null (QUE-02, Clarification 3) | QUE-02 |
| `nearby_clinics(p_lat, p_lng, p_radius_m, p_filters, p_cursor)` | `security invoker` (RLS on `clinics` already restricts to `status = 'active'` for non-staff; no elevated access needed) | any | location, radius, filter object, keyset cursor | Distance-sorted via the `location` GiST index, filtered (`is_active`, open-now, 24h, emergency, species, rating ≥), keyset paginated | CLN-01, CLN-02 |
| `my_upcoming_vaccinations()` | `security invoker` (caller's own RLS on `vaccinations` already scopes to their pets) | `owner` | — | Due/overdue vaccines across all of the caller's pets | PET-07 Home banner |
| `generate_vaccination_reminders()` | `security definer` (writes `notification_outbox` rows for arbitrary owners on a schedule, not the caller's own rows) | `pg_cron` (service role) | — | Inserts `notification_outbox` rows at 7-day, 1-day, and due-date marks; `dedupe_key` prevents duplicates on a double run | PET-07 |
| `custom_access_token_hook(event)` | `security definer` | Auth (invoked by GoTrue) | Auth event | Copies `profiles.role` into the JWT as `user_role` (research.md §8) | all RLS |
| `is_clinic_staff(p_clinic_id)`, `is_admin()`, `is_active_user()` | `stable security definer`, `set search_path = ''` | RLS helpers | — | Used inside policies to avoid a join per row | all clinic/admin policies |

## Policy-coverage check

`backend/supabase/scripts/check-policy-coverage.ts` (created in D02, `tasks.md` T173 — **fixed 2026-10-18,
this fix pass**: was a stale reference to T168, which is a different task) lists every policy
from `pg_policies` and fails CI if a policy has no matching pgTAP test reference (grepping the test suite
for the policy's table/policy name). This is a **standing CI gate from D02 through D08** — every RLS
policy in `data-model.md`'s Row Level Security summary, and every function/trigger in this file, must have
a pgTAP test or the build fails. It does not replace a human security review (see `plan.md` D08); it only
guarantees mechanical test coverage exists.
